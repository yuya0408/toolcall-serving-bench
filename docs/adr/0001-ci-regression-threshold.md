# ADR-0001: CI回帰ゲートの許容幅を Δselection >= -0.05 とする

- Status: Proposed（設計決定済み、CI自体は未実装）
- Date: 2026-08-08

## 結論（Summary）

- PRのゲートは2つ：selection ≥ 0.85（絶対の下限）と、mainの基準値からの低下が −0.05 以内。
- 毎晩の評価では consistency ≥ 0.90（n試行の全会一致、引数は文字列の完全一致）。本番の評価セットがそろうまでは記録だけで、失敗にはしない。
- 呼んではいけないツールを呼んだら、点数によらず失敗。LLM-as-JudgeはCIに入れない。
- CI自体はまだ実装していない（Proposed）。

## 背景と問い（Context and Problem Statement）

PRごとに評価ハーネスを実行し、基準を下回ったら fail させたい。
しかし LLM の出力は同じ入力・同じモデルでも非決定的にばらつく
（この非決定性そのものを consistency 指標として測っている）。

- 許容幅を0（完全一致でないと fail）にすると、ノイズによる±数%の揺れを
  「回帰」と誤判定し、PRが通らなくなる。開発体験が壊れ、ゲートが無視される。
- 許容幅を広げすぎると、実際の劣化（プロンプト変更やadapterのバグ）を
  見逃す。ゲートが名目だけになる。

`forbidden_tools`（呼ぶべきでないツールの呼び出し）は上記のノイズ議論とは
性質が違う。安全性に関わる失敗であり、頻度の問題ではない。

## 決定（Decision Outcome）

二段構成のゲートにする。`consistency` は同一入力を複数回実行しないと定義できず、
PR実行はスモーク15ケース×n=1（コスト・待ち時間の制約）なので、PRとNightlyで
評価する下限を分ける。

1. **PR時の絶対下限**：`selection >= 0.85`
2. **PR時の回帰許容**：`Δselection >= -0.05`（`main` の baseline 比、`eval/baselines/main.json`）
3. **Nightly時の絶対下限**：`consistency >= 0.90`（全ケース×反復ありで計算）。
   `consistency`の定義は`eval_bench/repetition.py`の`RepeatedCaseResult.consistent`
   に固定する：n試行**全会一致**（多数決やペア一致率ではない）、かつ引数は
   semantic judgeを介さず**文字列の完全一致**で比較する（表記揺れを許さない、
   arg_semanticより厳しい基準）。この0.90はこの定義に対して校正する。
   定義を緩めた場合は数値が変わるため、後継ADRを立てて明記する。
   **GT本番セット到達までは参考値として記録するのみでfail条件にはしない
   （活性化条件はConsequences参照）。**

`forbidden_tools` の呼び出しは、PR/Nightlyいずれでも上記のスコアに関わらず
即fail（減点ではない）。

semantic judge を含む LLM-as-Judge は CI に入れない。埋め込みjudge（決定的）のみ
CI で使う。これは既存の採点方針（LLM-as-Judgeを一次採点にしない）とも整合する。

## 影響（Consequences）

- ±0.05 以内の劣化はCIでは検出できない。これは既知のトレードオフとして
  ドキュメントに明記し、隠さない。
- consistencyの劣化はPRでは検出できず、Nightlyまで最大1日発覚が遅れる
  （n=1のPR実行では原理的に測れないため、これも既知のトレードオフとして明記する）。
- baselineとGTが結びついているため、GTを変更した場合は比較そのものが無意味になる。
  `manifest.json` のGTハッシュが変わったら回帰ゲートを自動スキップし警告を出す
  （GTを書き換えて数値を通す抜け道を防ぐ）。
- 閾値0.85 / 0.90 / -0.05 は初期値であり、Seed+Grounded本番GTで実測後に
  再校正する可能性がある。再校正した場合はこのADRを更新するか、後継ADRを立てる。
- 現状のサンプル数（14件）では`consistency`はケース単位の全会一致率なので
  1/14刻みの値しか取れず、0.90は12/14(≈0.857)と13/14(≈0.929)の間に落ちて
  どちらの側にも一致しない。GT本番セット（Seed+Grounded 120件前後）が揃うまでは
  この下限をCIで機械的に判定しない（参考値として記録するに留める）。
