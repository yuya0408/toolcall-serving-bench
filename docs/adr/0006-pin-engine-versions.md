# ADR-0006: エンジンの版を、疎通で通しで動いた組み合わせに固定する

- Status: Accepted（2026-10-27。本番3回のapplyで、追記を含めたこの決定どおりに動かした）
- Date: 2026-10-21

## Context

`scripts/gpu/setup.sh`は、llama.cppをmasterの先頭から取り、vLLMとtransformersを版を指定せずに入れていた。版は`~/out/versions.json`に記録するだけで、
applyごとに変わりうる。実際に、疎通（2026-10-18）と2回目のapply（2026-10-21）で、3日の間に3つが変わった。

| | 疎通（2026-10-18） | 2回目のapply（2026-10-21） |
| --- | --- | --- |
| llama.cpp | 848bbda | 8baabd5（b11785） |
| vLLM | 0.31.0 | 0.32.0 |
| transformers | 5.17.0 | 5.19.0 |
| torch | 2.13.0+cu132 | 2.13.0+cu132 |
| Qwen/Qwen3-8B・AWQ | b968826・4da05a8 | 同じ |

準備は毎回やり直し、パイロットは2回のapply（pilot-1・pilot-2）、本番はさらに別のapplyになる。版が変わると、同じエンジンの数字がapplyをまたいで
比べられず（たとえばpilot-1のllama.cppのlatencyと、pilot-2のllama.cppの第3パス）、パイロットで決めた件数nや分岐（ADR-0002・0003）が本番の版に当てはまる保証も無くなる。

## Decision

全applyで、疎通（2026-10-18）が通しで動いた組み合わせを使う。値は`scripts/gpu/pins.sh`の1か所に置き、`setup.sh`が読む。

- llama.cpp：848bbda9041decd87904f7eb5a2990863ecce03b（cloneの後にcheckoutする）
- vLLM：0.31.0、transformers：5.17.0（`uv pip install`で`==`を付ける）。torchはvLLMの依存で決まるものを使い、記録だけする
- モデル：Qwen/Qwen3-8B b968826、Qwen/Qwen3-8B-AWQ 4da05a8。ダウンロードでは固定しない（vLLMとtransformersはモデルをIDで読み、キャッシュの`main`の参照を使うため。
  リビジョンを指定して落とすと、その参照とずれる）。落としたリビジョンが違えば止める
- 準備の最後（`versions.json`を書いた直後）に、入ったものと`pins.sh`を突き合わせ、1つでも違えば準備を失敗させる（`SETUP_FAILED`）

この組み合わせにする理由：
- 4構成すべて（vLLM bf16・vLLM AWQ・llama.cpp・transformers_hf）がGPUの上で最後まで回り、runbook 4節の確認を通っている
- ADR-0005の容量の実測値（vLLM bf16 30,240、AWQ 99,552トークン）はこの版で測った
- llama.cppの848bbdaは、手元でテンプレートの描画（2026-10-20）と、1スロットの切り詰め（ADR-0005の追記2026-10-21）を確かめたb11716の1コミット先で、テンプレートに関わる変更は無い

## 検討した案

| 案 | 採否 | 理由 |
| --- | --- | --- |
| 2回目のapplyの版（b11785・0.32.0・5.19.0）に固定する | 却下 | 通しで動かしたのは容量の確認の2セルだけで、精度パス・latencyパスは動かしていない。新しい版を選ぶ理由（必要な修正）も無い |
| 固定せず、版を記録して結果に添える | 却下 | apply間で比べられなくなる（Context）。記録だけでは、ずれた後に戻せない |
| モデルもダウンロードでリビジョンを指定する | 却下 | キャッシュの`main`の参照とずれ、IDで読むエンジンが別のリビジョンを取りにいくおそれがある。2回のapplyで同じリビジョンだったので、照合して止める方で足りる |
| llama.cppのビルド済みバイナリを持ち回る | 扱わない | 準備の時間は縮むが、版の固定には要らない（runbook 3節で扱わないとした件と同じ） |

## Consequences

- 2回目のapply（2026-10-21）の`capacity-smoke`の結果（b11785・0.32.0）は、固定した版のものではない。判定（ADR-0005の追記）を直すための材料としてだけ使い、やり直しのapplyで固定した版で取り直す。
- 固定した版より新しい版の修正や速度改善は取り込まない。本番の後に版を上げる場合は、疎通をやり直してからこのファイルを改める。
- vLLM 0.31.0がPyPIから、848bbdaがGitHubから消えれば、準備ができなくなる（その場合は準備が止まるので、黙って別の版で測ることはない）。
- `accelerate`と、vLLMが引き込む依存（torchなど）は固定しない。torchは`versions.json`に記録する。
